# 역할 4 — Structured Output과 입지점수 계산 Tool

담당자: **효주** · 브랜치: `feature/scoring` · 선행 문서: [공통 계약](00_공통계약.md)

## 목표

6명이 공유할 데이터 계약을 한 곳에 선언하고, 같은 입력에는 같은 점수를 반환하는 계산 Tool을 직접 개발한다. 이 명세서는 계산 구현을 제공하지 않는다.

## 파일별 개발 지시

| 파일 | 개발할 내용 |
|---|---|
| `models/schemas.py` | 공통 Pydantic 모델·payload·검증 규칙. 이 파일의 유일한 수정 담당자 |
| `tools/scoring_tools.py` | `calculate_market_score`, 지표 정규화·총점·confidence·누락 처리 |
| `tests/test_schemas.py` | 필수 필드·타입·범위·상태 간 일관성·직렬화 테스트 |
| `tests/test_scoring.py` | 수치 예제·경계값·누락·재현성 테스트 |
| `data/mock/scoring_*.json` | 계산 입력·기대 결과 fixture |
| `docs/scoring.md` | 지표 매핑, 산식·임계값·반올림·confidence·비교 정책 |

Memory 모델은 역할 2의 설계를 반영하고 API payload는 역할 1과 합의한다. 담당자가 단독으로 모든 데이터 의미를 결정하지 않는다.

## 입력/출력 계약

`calculate_market_score(scoring_input: ScoringInput) -> ToolResult`를 제안한다. 정상 data는 MarketScore를 직렬화한 사전이다. 단독 MarketScore 반환과 ToolResult 반환을 혼용하지 않는다.

입력에는 상권 ID, 사용자 조건, 분석 기간, Tool 이름별 정규화 결과를 담는다. 실패한 ToolResult의 빈 data를 0으로 계산하지 않는다. 지역·기간·단위가 맞지 않으면 계산을 거절하거나 해당 지표를 누락 처리하고 이유를 남긴다.

최종 응답 선언은 StudySpotResponse와 AreaRecommendation을 사용한다. 역할 5가 추천 근거를 조립하고 역할 6은 이를 렌더링한다. 본 역할은 출력 구조·범위·불변식을 검증한다.

## 고정 배점

| 항목 | 필드 | 최대점 |
|---|---|---:|
| 학원·교육 수요 | academy_demand_score | 25 |
| 타깃 연령 방문자 | target_customer_score | 20 |
| 지하철 출구 통행량 | station_traffic_score | 15 |
| 저녁·주말 유동성 | activity_score | 15 |
| 임대비용 적합성 | rent_score | 15 |
| 경쟁점포 포화도 | competition_score | 10 |

기본 배점 합은 100이며 total_score는 세부 점수 합과 일치해야 한다. '학원이 많아 보인다' 같은 LLM 판단을 수치 입력으로 쓰지 않는다.

## 개발 전에 작성할 계산 설계

각 항목에 대해 원천 지표·단위·관측 기간·좋은 방향·정규화 기준·이상치 처리·필수 데이터·수치 예제를 작성한다. 임대 적합성은 보증금과 월세를 구분하고, 경쟁도는 점포 수·반경·기준 시점을 명시한다. 후보 집합 상대 정규화를 쓰면 후보 추가로 점수가 바뀔 수 있으므로 고정 기준 방식과 비교한 뒤 선택 이유를 적는다.

기존 규격에는 상세 산식이 없다. 임계값이나 통계값을 실제 데이터처럼 발명하지 말고 정책상 설정값과 관측값을 구분한다. 반올림 자리·동점 정렬 기준·confidence의 의미와 산식을 정한다. confidence를 검증되지 않은 성공 확률이라고 설명하지 않는다.

누락 점수의 nullable 확장은 공통 계약의 **추가 제안**이다. 먼저 스키마 PR로 확정하고 소비 모듈에 알린다. 채택 시 None을 0으로 표시하지 않고 관측 가능한 점수만 합산한다. 전체 누락은 계산 가능한 추천에서 제외한다. 다른 정책을 채택하면 총점 불변식까지 공통 문서를 함께 변경한다.

Mock이 하나라도 계산에 쓰이면 계산 ToolResult.is_mock=True로 전파한다. 혼합 출처는 evidence에 개별 표시한다. 데이터 커버리지·Mock·최신성을 confidence에 반영하는 방법을 명시적으로 합의한다.

## 의존 모듈

역할 1과 역할 5의 데이터 Tool → ScoringInput → 본 Tool → 역할 5의 AreaRecommendation 조립 → 역할 6 UI. 역할 3은 출력 검증 실패를 처리한다. 역할 2는 MarketScore를 상태에 저장하되 재계산하지 않는다.

## 테스트 범위

| ID | 상황 | 통과 조건 |
|---|---|---|
| SCR-01 | 사람이 별도 계산한 고정 예제 | 예상 세부 점수·총점·confidence 일치 |
| SCR-02 | 같은 입력 반복·순서 변경 | 같은 결과, 상태·LLM 의존 없음 |

| SCR-04 | 실제 0·일부 누락·전체 누락 | 0과 None 구별, 누락 표시·신뢰도 정책 준수 |
| SCR-05 | 실/Mock 혼합 | Mock 출처가 최종 결과까지 유지 |
| SCR-06 | 단위·기간·상권 불일치 | 잘못된 비교 거절 또는 명시적 누락 |

기대값을 구현 함수로 다시 계산해 테스트하지 않는다. 독립적인 수치 예제를 사용한다.

## 완료 조건

모든 공통 모델과 payload의 타입·단위·누락 규칙이 확정되고, 다른 역할이 모델을 중복 정의하지 않아도 개발 가능하다. 산식 문서와 독립 예제 테스트가 일치하고 총점·Mock·confidence를 추적할 수 있다.

## 금지사항

LLM 점수 생성, 누락 원천값 0 대체, 검증 없이 배점 변경, API 직접 조회, UI에서만 검증하도록 위임, 합의 없는 필드명 변경을 금지한다.
