# 역할 6 — Streamlit UI·통합 테스트

담당자: **명하** · 브랜치: `feature/ui` · 선행 문서: [공통 계약](00_공통계약.md)

## 목표

사용자가 조건을 입력하고 추천 근거·누락·Mock 여부를 이해하며, 외부 행동 내용을 확인하고 승인할 수 있는 화면을 직접 개발한다. 전체 흐름 테스트를 맡되 다른 담당자의 단위 테스트를 대신하지 않는다.

## 파일별 개발 지시

| 파일 | 개발할 내용 |
|---|---|
| `app.py` | 조건 입력·대화·추천·누락/Mock 표시·승인/거절·실행 상태 |
| `tests/test_ui.py` | 상태별 렌더링·입력 유지·승인 의도 전달 테스트 |
| `tests/test_integration.py` | Mock 기반 사용자 시나리오·모듈 연결 테스트 |
| `data/mock/ui_*.json` | StudySpotResponse 상태별 fixture |
| `docs/demo_scenarios.md` | 정상·조건 변경·오류·승인 데모 순서와 기대 화면 |

README 변경은 역할 5에게 전달한다. State 내부 갱신이나 모델 변경은 직접 하지 않는다.

## 입력/출력 계약

화면은 BusinessConditions 필드에 맞춰 지역·보증금·월세·타깃 연령·시작/종료 시간·우선순위를 받는다. 예산 단위는 원이며 빈 값과 0을 구별한다. 사용자 메시지와 조건을 AgentRequest로 전달한다.

호출 경계는 `run_analysis(request, context) -> StudySpotResponse`다. data Tool·점수 Tool·Store를 UI가 직접 호출하지 않는다. Context는 앱 실행 계층에서 관리하고 사용자가 user_role을 입력해 권한을 바꾸는 화면을 만들지 않는다.

반환 모델 필드로만 화면을 만든다. 추천 순서·점수는 Agent 결과를 유지한다. 화면에 필요한 식별자가 없으면 이름 문자열로 저장하지 말고 역할 4·5에 계약 확장을 요청한다. **추가 제안:** AreaRecommendation에 commercial_area_id를 추가하여 관심 상권 선택을 연결한다.

## 상태별 화면 요구

| 상태 | 화면·행동 |
|---|---|
| need_more_information | 누락 필드와 추가 질문, 이미 입력한 값 유지 |
| success | 후보 최대 3개, 총점·항목별 점수·장점·위험·출처·confidence |
| no_result | 빈 결과 원인·조건 완화 안내. 시스템 오류라면 오류임을 구분 |
| approval_required | 전송/일정 내용·대상·승인/거절 버튼. 승인 전 실행 완료 표현 금지 |

누락 세부 점수 `None`은 '데이터 없음(총점에는 0점 반영)'으로 표시한다. 이를 실제 관측된 0점으로 바꾸거나 화면에서 총점을 재계산하지 않는다. Mock은 관련 근거와 추천에 눈에 띄게 표시하고 실/Mock 혼합 여부를 숨기지 않는다. confidence가 검증된 사업 성공 확률인 것처럼 표현하지 않는다.

승인 버튼은 action_id·payload 버전에 묶인 의도만 Agent로 보낸다. 승인 내용이 변경되면 다시 표시한다. 버튼 중복 클릭·Streamlit 재실행으로 같은 행동이 재전송되지 않도록 UI 처리하고 서버 중복 방지와 함께 테스트한다. 거절 시 실행되지 않았음을 표시한다. 실제 행동 Mock은 '실제 전송/등록되지 않음'이라고 표시한다.

새 세션·후속 질문의 상태 관리는 역할 2·5를 사용한다. session_state에는 화면 입력·선택 등 UI 상태만 두고 별도 분석 결과의 진실 원천을 만들지 않는다.

## 의존 모듈

역할 4의 StudySpotResponse fixture로 먼저 화면을 개발한다. 역할 5의 Agent 진입점을 연결하고 역할 2의 세션 유지, 역할 3의 오류·승인, 역할 1의 Mock Fallback을 통합 검증한다. 타 모듈 버그는 해당 담당자에게 테스트 재현 절차와 함께 전달한다.

## 테스트 범위

| ID | 시나리오 | 통과 조건 |
|---|---|---|
| UI-01 | 상태별 fixture | 모델 오류 없이 해당 화면 표시 |
| INT-01 | 완전한 조건·정상 Mock | 최대 3개 추천, 점수 일치, Mock 표시 |
| INT-02 | 월세·시간 누락 | 추가 질문, 데이터 Tool 호출 없음 |
| INT-03 | API 미지원 지역·0개 후보 | no_result, 허위 추천 없음 |
| INT-04 | timeout 후 Fallback | 출처·Mock·오류 설명 보존 |
| INT-05 | 일부 지표 누락 | 데이터 없음·위험 표시, UI 임의 계산 없음 |
| INT-06 | 후속 질문·조건 변경 | 기존 값 유지·변경값 반영·새 점수 표시 |
| INT-07 | 승인 전·거절·중복 클릭 | 미승인 행동 0회, 승인 행동 최대 1회 |
| INT-08 | 다른 세션·다른 사용자 | 이전 사용자 정보 미노출 |
| INT-09 | Guardrail 차단·반복 제한 | 앱 중단 없이 안내, 비밀정보 미노출 |

기본 통합 테스트는 가짜 모델과 외부 호출 없는 fixture로 재현한다. 실제 LLM·API 연동 검증은 별도 실행하고 Mock 테스트 통과와 구분한다.

## 완료 조건

모든 response 상태와 오류·누락·Mock·승인 흐름이 표현되고, 필수 시나리오가 재현 가능하다. 점수는 계산 Tool 출력과 일치하며 사용자 변경 조건이 반영된다. 각 담당자 단위 테스트 결과와 전체 통합 결과를 구분해 공유한다.

## 금지사항

UI의 직접 데이터 Tool 호출, 점수 재계산, 자유 텍스트를 임의 파싱해 모델 대체, State/Store 이중 구현, Mock 숨김, 화면 클릭만으로 외부 Tool 직접 실행, API 키의 화면·로그 노출을 금지한다.
