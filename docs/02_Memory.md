# 역할 2 — Agent State·Store·단기/장기 Memory

담당자: **소유** · 브랜치: `feature/memory` · 선행 문서: [공통 계약](00_공통계약.md)

## 목표

현재 대화 조건을 잃지 않고 후속 질문에 이어서 분석하며, 사용자별 장기 선호를 안전하게 분리한다. 상태의 수명과 갱신 규칙을 설계하고 직접 구현한다.

## 파일별 개발 지시

| 파일 | 개발할 내용 |
|---|---|
| `memory/store.py` | 사용자별 선호 조회·저장, `save_user_preferences`, `save_shortlist`, 저장소 연결 |
| `memory/state.py` (추가 제안) | State 초기화·갱신·요약·체크포인트 연결; 모델 자체는 재선언하지 않음 |
| `tests/test_memory.py` | 세션 복원·사용자 격리·조건 변경·저장 실패 테스트 |
| `docs/memory.md` | 상태 수명, 키 구조, 저장 시점, 재시작 보존 범위, 삭제 정책 |

`BusinessConditions`, `RuntimeContext`, `StudySpotState`, `UserPreferences`의 의미와 타입안을 역할 4에게 전달한다. `models/schemas.py`는 역할 4만 수정한다.

## 입력/출력 계약

- RuntimeContext는 실행 계층에서 받는다. Store의 user_id는 사용자 프롬프트에서 읽지 않는다.
- State 필드는 공통 계약을 그대로 사용한다. Tool 결과는 호출 ID로 구분하여 상권·기간이 다른 조회가 덮어쓰이지 않게 한다.
- `save_user_preferences(preferences, context) -> ToolResult`, `save_shortlist(commercial_area_ids, context) -> ToolResult`를 제안한다. 정상 data는 저장한 허용 필드 또는 저장 ID 목록이며, 실제 저장 완료 후 success를 반환한다.
- 내부 조회 함수 `load_user_preferences(context) -> UserPreferences | None`를 제안한다. 미등록 사용자와 저장소 장애는 구분한다.
- 저장소 오류는 Tool 경계에서 TOOL_INTERNAL_ERROR로 변환한다. 원본 사용자 정보는 오류에 넣지 않는다.

## 상태 수명과 갱신 규칙

| 종류 | 담을 것 | 수명·권장 키 |
|---|---|---|
| Runtime Context | user_id/session_id/user_role | 호출 중 불변 |
| 단기 State·체크포인트 | 조건·메시지·현재 후보·Tool 결과·승인 대기 | 사용자+세션별 |
| 장기 Store | 선호 지역·예산·타깃 고객·우선순위·관심 상권 | 사용자별, 세션 종료 후 유지 |

추가 제안: 새 세션은 장기 선호로 초기화하되 현재 사용자의 명시적 조건을 우선한다. 필드 미제공은 기존 값 유지, 명시적 초기화는 별도 의도로 구분한다. `target_customer` → `target_age`, `preferred_regions` → 현재 preferred_region 변환은 선택 기준을 문서화하고 여러 지역 중 임의 선택하지 않는다.

조건 변경 시 영향받는 후보·점수·조회 결과를 무효화한다. 조건·기간별 캐시 재사용 가능 여부는 역할 3·5와 맞춘다. 이전 점수를 새로운 조건 결과로 표시하지 않는다. 대화 요약은 과거 메시지에 적용하고 최신 BusinessConditions는 별도 구조로 유지한다.

장기 저장은 사용자가 저장을 요청·선택한 선호에 한정한다. 현재 대화의 모든 수정값을 자동 영구 저장하지 않는다. 전화번호·이메일·정확한 주소는 역할 3의 마스킹을 거친 후 저장한다. 실제 행동의 수신 주소 등은 장기 선호에 넣지 않는다.

## 의존 모듈

역할 4: 공통 모델 선언. 역할 3: 마스킹·승인 상태 검증. 역할 5: 세션 식별·상태 읽기/쓰기 연결. 역할 6: 새 대화·후속 입력·관심 저장 의도를 Agent로 전달.

역할 3은 요약 훅을 연결하고 본 역할은 요약 상태 갱신을 담당한다. UI가 별도 장기 Store를 만들지 않는다. API 캐시는 장기 사용자 선호와 분리한다.

## 테스트 범위

| ID | 상황 | 통과 조건 |

| MEM-09 | 명시적 초기화·동시 갱신 | 초기화/부분 수정 구별, 최신 갱신 유실 방지 |

## 완료 조건

세션별 State와 사용자별 Store가 분리되고 후속 질문·조건 변경·새 세션 복원이 검증된다. 인메모리 저장소만 구현한 경우 재시작 후 보존되지 않는다는 한계를 기록하고 영속 저장 완료라고 표시하지 않는다. 키·갱신·요약·삭제 규칙을 역할 5에게 인계한다.

## 금지사항

전역변수에 전체 사용자 상태 저장, 공통 모델 중복 선언, 사용자 입력의 user_id 신뢰, 최신 조건을 요약문으로 덮어쓰기, 모든 대화 원문 영구 저장, Mock 저장을 실제 영속 저장으로 표시하는 행위를 금지한다.
