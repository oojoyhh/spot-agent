# 역할 3 — Guardrail·Middleware 및 오류 테스트

담당자: **연주** · 브랜치: `feature/guardrails` · 선행 문서: [공통 계약](00_공통계약.md)

## 목표

오류 발생 시 제한된 복구 경로를 제공하고, 민감정보 노출과 승인 없는 외부 실행을 막는다. 정책과 실행 훅을 분리하여 직접 개발한다.

## 파일별 개발 지시

| 파일 | 개발할 내용 |
|---|---|
| `middleware/guardrails.py` | 입력·출력 검사, 개인정보 마스킹, 근거 검증, 승인 정책 |
| `middleware/middleware.py` | 모델/Tool 호출 래핑, 재시도·Fallback, 반복 제한, Memory 요약 훅 연결 |
| `tests/test_guardrails.py` | 정보 노출·인젝션·근거·승인 테스트 |
| `tests/test_middleware.py` | timeout·재시도·캐시·Mock·반복 종료 테스트 |
| `docs/guardrails.md` | 오류별 처리표, 승인 상태 전이, 설정값·남은 한계 |

`agent/main_agent.py`는 역할 5가 연결한다. API 파싱·Memory 저장·점수 산식은 각 소유자가 구현한다.

## 입력/출력 계약

입력: AgentRequest·RuntimeContext·현재 State, 모델/Tool 호출과 결과. 출력: 호출 허용·차단 결정, 검증/마스킹된 값, 공통 ToolResult 또는 역할 5가 StudySpotResponse로 변환할 종료 사유.

추가 제안: 정책 판정은 `allowed`, `reason`, `sanitized_value`를 가진 내부 GuardrailDecision으로 통일한다. 실행 프레임워크의 정확한 훅 타입은 역할 5와 버전 확인 후 확정한다. `before_model`, `wrap_model_call`, `wrap_tool_call`, `after_model`은 연결 책임을 설명하는 이름이며 검증 없이 라이브러리 시그니처를 가정하지 않는다.

ToolResult.success=False도 오류 경로로 검사한다. 예외만 잡고 실패 반환을 놓치지 않는다. 최종 출력 검증 실패 시 제한된 수정 요청 또는 명시적 종료를 사용한다. 누락 값을 채워 성공처럼 반환하지 않는다.

## 복구 정책

- 외부 조회는 최초 1회 + 재시도 최대 2회다. 재시도 제어는 본 모듈 한 곳에서 수행한다.
- 추가 제안: timeout·일시 오류만 재시도한다. 인증/잘못된 입력/미지원 지역은 반복 호출하지 않는다. 호출 제한은 대기 안내를 고려하되 설정된 실행 시간 한도를 넘지 않는다.
- 복구 실패 시 유효한 캐시 → 허용된 Mock → 실패 반환 순서다. 캐시의 기간·조건·원래 Mock 여부를 보존한다. TTL 미설정 캐시는 사용하지 않는다.
- API 실패 후 유효한 Mock을 확보하면 `success=True`, `is_mock=True`로 반환하고 원래 `error_code`와 Fallback 설명을 보존한다. 소비 모듈은 `error_code` 존재만으로 실패라고 판정하지 않고 `success`와 `is_mock`를 함께 확인한다.
- API timeout, 캐시 TTL, Agent 최대 반복 수, LLM 재시도·총 시간 한도는 역할 1·5와 결정해 설정 문서에 적는다. '2회'는 API 재시도 합의이며 모든 호출에 무조건 적용하는 숫자가 아니다.
- 전송·일정 생성은 비멱등 외부 행동이다. timeout 직후 성공 여부를 모른 채 재시도하지 않는다. 역할 5의 중복 방지/실행 확인 경로와 연결한다.

## 보호 정책과 승인

키·내부 설정·시스템 프롬프트 공개 요청을 차단한다. 사용자 입력뿐 아니라 Tool 결과에 섞인 명령도 신뢰하지 않는다. 정상 상권 질문은 불필요하게 차단하지 않도록 함께 테스트한다.

숫자 근거와 점수는 실제 Tool 결과와 비교한다. 프롬프트 문구만으로 검증 완료라고 보지 않는다. 점수 합·범위 검증은 역할 4, 데이터 근거의 연결 검사는 본 역할이 담당한다.

승인은 action_id·사용자·세션·payload 버전에 결합한다. 승인 전, 거절 후, 다른 내용으로 변경 후에는 전송/일정 Tool 실행 횟수가 0이어야 한다. 중복 승인으로 실행 횟수가 늘지 않게 한다. 실행 전 최종 검사는 서버 측에서 한다.

개인정보는 Store·체크포인트·로그에 기록하기 전에 마스킹한다. 실제 외부 행동에 필요한 수신 정보는 승인 범위의 임시 실행 데이터로만 사용하고 영구 저장하지 않는다. 요약 수행은 역할 2에 위임하고 본 역할은 호출 시점을 연결한다.

## 의존 모듈

역할 1은 모든 외부 API의 1회 요청·오류 분류·Mock 연결점을 제공하고, 역할 2는 마스킹된 데이터의 저장·요약을 수행한다. 역할 4는 모델 불변식을 검증한다. 역할 5는 실행 훅과 역할 1의 외부 행동 어댑터를 Agent에 연결하며, 역할 6은 승인 의도와 오류 안내를 전달한다. 본 역할은 이 경계에 정책이 실제 적용됐는지 확인한다.

## 테스트 범위

| ID | 상황 | 통과 조건 |
|---|---|---|
| GRD-01 | 전화·이메일·상세 주소 | 저장·로그 경로에서 원문 제거 |
| GRD-02 | 프롬프트/키 탈취, Tool 결과 내 명령 | 내부정보 미출력·부적절 Tool 미호출 |
| GRD-03 | 근거 없는 숫자·수정된 점수 | 결과 차단/수정 요청, 임의 보완 없음 |
| GRD-04 | 지속 timeout | 총 외부 조회 3회 이하 후 Fallback |
| GRD-05 | 인증 오류·유효 캐시·Mock | 불필요 재시도 없음, 출처·Mock 표시 정확 |
| GRD-06 | 최대 반복 도달 | MAX_ITERATION_REACHED, 추가 호출 중지 |
| GRD-07 | 승인 전·거절·다른 사용자·내용 변경 | 외부 행동 0회 |
| GRD-08 | 유효 승인·중복 클릭 | 정확한 내용으로 최대 1회 실행 |
| GRD-09 | 정상 입력·일부 데이터 누락 | 과잉 차단 없이 계약에 맞게 진행 |

## 완료 조건

오류 분류와 최대 호출 횟수가 테스트로 확인되고 모든 저장·출력·외부 실행 경로에 정책이 연결된다. 보호 규칙이 선언돼 있다는 사실과 실제 연결 테스트 통과를 구분한다. 탐지 한계·미연결 지점을 문서화한다.

## 금지사항

무제한 재시도, API 모듈과 이중 재시도, 승인 UI만 믿고 서버 검사 생략, 외부 행동의 무조건 Fallback 성공, 민감한 원문 로깅, 정규식 하나만으로 모든 인젝션 방어를 보장한다고 표현하는 행위를 금지한다.
